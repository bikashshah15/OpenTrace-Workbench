# Domain contract `opentrace.evidence` major 3.0

Contract version **3.0** · schema version `3.0` · capability version `3.0` · I3 (a private planning record (not in this export) v1.0.1, frozen 2026-10-14).

Major 3.0 exists because I3 adds operations, evidence kinds, claim types and missing-evidence reasons, which are breaking under the
v2 version rules (`contracts/evidence/v2/README.md`: adding enum members needs a new major). **Nothing under `contracts/evidence/v1/`
or `contracts/evidence/v2/` is changed**; 1.0 and 2.0 stay valid and supported. 3.0 retains every 2.0 member so mixed outputs validate.

| File | Purpose |

## Carriage and the contract token

Payloads travel as in 1.0 and 2.0. A major 3 payload is processed **only** when its NLIP message also carries the contract token
submessage `Format: token`, `Subformat: contract_opentrace-evidence`, `Content: "3.0"`; the receiver echoes the token. The
(major, token) pair must agree: a 3.0 payload without the token, a 3.0 token with a 1.0 or 2.0 payload, and a 2.0 token with a 3.0
payload are all answered by a **1.0** rejection `unsupported_schema_version`. B's 1.0-profile `capability_response` lists
`contract_versions ["1.0","2.0","3.0"]`; A selects the target contract per schedule (the I2 schedule stays at 2.0). A 1.0- or 2.0-only
peer only ever receives messages valid for its contract.

## Differences from 2.0

| Area | v3.0 |
|---|---|
| Operations | `repo_inventory`, `osv_inventory_match`, `github_sbom_import` (the 3.0 capability lists only these; the I2 operations remain 2.0-only) |
| Evidence `kind` (new) | `repo_source_scope`, `manifest_inventory`, `manifest_status`, `osv_inventory_scope`, `hosted_sbom_scope`, `hosted_package_table`; `advisory_match` and `osv_query_complete` are reused (`advisory_match` gains optional `ecosystem`, `package`, `version_queried`, `version_original`; `osv_query_complete` entries carry `version_state`) |

| `missing_evidence.reason` | the 2.0 values plus `manifest_unsupported`, `manifest_malformed`, `manifest_too_large`, `lock_absent`, `version_unresolved`, `non_registry_source`, `unsupported_ecosystem`, `output_limit`, `rate_limited`, `timeout`, `forbidden`, `not_found`, `credential_unavailable`, `redirect_refused`, `invalid_response`, `hosted_not_acquired`, `query_rejected`, `unresolved_identity`, `report_too_large`, `unsupported_spdx_version`, `http_error` |
| Result limits | unchanged: at most 1000 evidence items and 1000 claims; at most 4 produced artifacts of 1 MiB. Inventory scale is carried by typed tables |

### Typed tables (produced artifacts, canonical JSON, digest-pinned)

- **Occurrence table** (`opentrace.occurrence_table/1`, evidence kind `manifest_inventory`): header `repo`, `commit`, `path`, `kind`; `rows` sorted bytewise by `locator`, unique within the manifest; every row has `locator`, `ecosystem`, `name_original`, `name_normalized`, `version_original`, `version_state`, `direct`, `scope`, `scope_basis`, `integrity_recorded`, `source_kind` (npm rows also `installed_name`, `alias`; Go rows `replaced_by` when replaced).
- **Hosted table** (`opentrace.hosted_table/1`, evidence kind `hosted_package_table`): `lane: "hosted_unbound"`; `rows` sorted bytewise by `spdx_id`, unique; every row has `spdx_id`, `name_original`, `name_normalized`, `ecosystem`, `version_original`, `version_state`, `purl`, `source_path` (always `null`: the hosted report carries no manifest path).

### Core rules V12–V16 (`validate_v3.py`; the 2.0 rules V7–V10 still apply)

V12 typed tables (digest equals `table_artifact` and `table_digest`, row count, required fields, sorted and unique by the typed key) → `table_integrity`; V13 hosted binding (`observed_revision` null; a supported claim over hosted evidence must be `hosted_inventory_recorded_unbound` over a downloaded report; `revision_binding` and `document_binding` are the constant `unbound`) → `hosted_binding_violation`; V14 a supported `manifest_inventory_recorded` needs a parsed manifest with no unparsed constructs → `partial_promoted`; V15 a zero-result claim needs an `exact` query entry (plus the 2.0 V8 conditions) → `incomplete_query_claim`; V16 a supported `advisory_matches_version` needs a record explicitly not withdrawn (`withdrawn` is `false`) → `withdrawn_promoted`.

## Status meanings, version rules

Result statuses and run states are as in 1.0 and 2.0. `schema_version` is `"3.<minor>"`; receivers accept major 3 with any minor. A later change that adds enum members or tightens a closed object would need major 4. Unknown optional fields keep the 1.0 rule: ignored at the open levels, never used as evidence.
