# Analysis identity contract v1

`opentrace.analysis_identity/1` pins one repository, one resolved commit, the scan selection and a session generation. Its `analysis_digest` is the canonical SHA-256 of exactly `{canonical_url, commit_sha, scan}`. Session identifiers, input spelling and resolution time are deliberately outside that digest.

Validation has two layers. `validate_identity_structure` checks object shape, required and allowed properties, types, enumerations and ASCII patterns using only the standard library; the Draft 2020-12 JSON Schema expresses the same structural rules. Timestamp syntax is structural, while calendar validity (such as rejecting February 30) is semantic. The schema intentionally uses no `format` keywords. `validate_identity` first runs the structural checks, then validates the timestamp calendar, recomputes `analysis_digest` and checks that `repository.canonical_url` agrees with `owner` and `name`. Generation follows JSON Schema integer semantics: a finite integral number is accepted structurally, while `build_identity` normalizes it to a Python integer.

Examples are separated by the layer they violate: `valid/` passes both layers; `invalid/` violates schema and structural validation; `semantic_invalid/` passes schema and structural validation but fails semantic validation. In particular, `digest_mismatch.json` cannot be rejected by JSON Schema, so it is a semantic-only invalid example. Tests always run both stdlib layers; Draft 2020-12 schema-engine checks run only with the pinned development dependency `jsonschema==4.23.0`.
